## Build order (each step its own branch and PR, test mode only)

1. **Settings and a status check**: read the 2 keys (add them to `docs/settings.md`, `.env.example`, `docs/security.md`), and an Admin check that the key works, like the Anthropic setup check on `/admin/found`. **Built 14th November 2026**: Admin, Payments (`/admin/payments`) shows whether both keys are there, look right, are the same mode, and are test keys, and a Test the Stripe key button reads the account (business name, statement line, country, Stripe Tax status) without charging or changing anything (`lib/stripe-setup.ts`, tested; `lib/stripe.ts` is the 1 place the site calls Stripe, with plain web requests, no Stripe library). No SQL.
2. **Products and prices** created from `lib/pricing.ts` by a script or an admin button, so Stripe and the site never disagree. The free launch coupon (100% off) with an end date.
   **Built 14th November 2026**: Admin, Payments now lists the 7 prices (3 single posts, Clinic pass and Plus monthly and yearly) and the `FREE-LAUNCH` coupon, says which are in Stripe, and a **Create or update in Stripe** button adds what is missing (`lib/stripe-catalog.ts` works out what should exist from `lib/pricing.ts`; `lib/stripe-catalog-sync.ts` talks to Stripe). It never deletes, works only with a test key, and can be pressed again safely. Products have fixed ids (`kestrel_post_support`, `kestrel_clinic_pass` and so on) and prices are found by lookup key, so a changed number in `lib/pricing.ts` makes a new Stripe price and switches the old one off. The coupon is 100% off, once, **single posts only, never a pass**. Stripe cannot edit a coupon's end date, so the end date is `FREE_LAUNCH_ENDS` in `lib/pricing.ts` (31st July 2027, Steve's "July 2027, I think") and checkout asks `freeLaunchOpen()` before applying it. Prices are marked tax exclusive. No SQL.
3. **Checkout for a single post**: when a clinic sends a job for review, it goes through Checkout first; $0 with the launch coupon and no card asked (`if_required`). Record each payment against the job. A webhook (`/api/stripe/webhook`, signature checked with `STRIPE_WEBHOOK_SECRET`) marks it paid. Every new table gets row level security and access tests (`npm run test:db`), and SQL for both databases.
   **Built 14th November 2026 (migration 0048, run on both databases by Steve, 14th November 2026).** Design agreed with Steve: **the card is saved when a job is sent for review and charged only when Kestrel approves it** (Stripe Checkout in `setup` mode, then an off session payment on approval), so a clinic never has to come back to pay, a job that is not approved is never charged, and the role band is checked by the reviewer before any money moves.
