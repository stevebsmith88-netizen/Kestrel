### P1-60 in plain English (for the record)

When a candidate presses **Fill in from my resume**, the reading happens in a Vercel "function", a short burst of computer time on Vercel's servers. Vercel lets each project choose which city those functions run in. If it is Montreal (Vercel's code for it is `yul1`), the resume is read in Canada, next to the database, which is in Canada too. If it is left at Vercel's usual default (Washington, D.C., code `iad1`), the resume travels to the United States for the second or so it takes to read it, and the text is then thrown away.

What I could check: the code does not choose a region (`vercel.json` only sets the daily job), so the project setting in Vercel decides. The lawyer pack (since 31st October) says the functions run in Montreal, "set on 31st October 2026", but I cannot see Vercel's settings to confirm it, and the audit could not either.

What to check, in each Vercel project (live and demo), no change needed unless it is wrong:

1. Open the project, then **Settings**, then **Functions**.
2. Look at **Function Region**. It should say Montreal, Canada (`yul1`) if the 31st October setting stuck.
3. If it does not, it can be changed there. On the Hobby plan only 1 region can be chosen, and Montreal is allowed; changing it takes effect on the next deployment. Check the page shows Montreal as available on your plan before relying on this.
4. Tell me what it says. If it is Montreal, the lawyer pack is right as written, and I will remove the "not yet confirmed" note from the new page. If it is not, the privacy policy's "Where your information is kept" section is still true (it already says the hosting provider may handle requests outside Canada), but the lawyer should hear it either way.

### The check query for the live and demo databases (finding B-06)

Run before and after the SQL, in the Supabase SQL editor. It only reads.

